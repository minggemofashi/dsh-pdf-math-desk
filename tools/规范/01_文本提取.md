# 01 任务①：按需提取课本原文

先读 `00_共同约定.md`（公式与输出规范）。本文件只讲流程。

目标：把指定页码 / 指定段落的原文，还原成带 `$` `$$` 的干净文本，**整段包在一个代码块里**交给用户。

---

## 第 0 步 工作单位：一章一个文件

数学教材的章节相对独立，所以**按章拆分就是最合适的工作单位**——不是为了硬凑上下文，是拆了更准、更省。

| 好处 | 具体 |
| --- | --- |
| 上下文小 | 一章 20–40 页 ≈ 2–5 万 token，比整本低一个量级 |
| 定位准 | 只带这一章，不会串到别的章 |
| 便宜 | 每次请求只带一章，输入 token 自然低 |
| 不撞上限 | 100 MiB / 1000 页两条硬限基本碰不到 |

拆一次（命名自带页码，`resolve` 靠它反查，**别手工改名**）：

```powershell
$根 = "D:\数学书库"
& "$根\工具\py.cmd" "$根\工具\pdfkit.py" split "书库\高等数学\高等数学第8版下册.pdf" --ranges "1-30,31-68,69-104" --titles "多元函数,重积分,曲线积分"
```

产物：`分片\高等数学第8版下册\高等数学第8版下册_c01_p1-30_多元函数.pdf`

### 硬上限（什么时候非拆不可）

| 上限 | 数值 |
| --- | --- |
| 单个文档页数 | 1000 页 |
| 单请求文档文字 | 8 MiB（≈280 万汉字） |
| 上下文 | 1M token |
| 单次输出 | 16000 token（约 10–20 页正文） |

整册 500 页也能整本塞进去（40–60 万 token），但按章更省更准，所以默认按章。

### 撑爆了怎么补救（按顺序）

1. **`HTTP 400`** —— 官方明确不静默截断，你能立刻知道。缩小 `--pages` 重问，`file_id` 可复用，解析费不重复掏。
2. **输出被截断** —— 每次 ≤10 页，分几次要。
3. **跨章问题** —— 一次请求最多引用 20 个文档，把相关两三章一起给即可，**不需要合并文件**。
4. **单册 > 1000 页** —— 这时才必须拆。
5. **终极兜底：本地看图**（第 4 步的 B 通道），不吃任何长上下文。
6. **会话越问越慢** —— 多轮中引用过的文档会完整保留、每轮重新携带；一个会话别超过 2–3 轮，`dsfile.mjs` 提问是独立请求不累积。

## 第 1 步 定位页码范围

三种情形，按用户给的信息选：

**先取书（顺序不能反）：**

```powershell
& "$根\工具\py.cmd" "$根\工具\pdfkit.py" lookup <书名或作者关键词> --page <原书页码>
```

- `split_books` 非空 → **用分片**，`result` 直接给出「哪一片 + 片内第几页」，后面的 `--pages` 用 `local_page`。
- `split_books` 为空、`full_books` 非空 → 只有全本：整本按 `第 3 步` 直接提取（不必先拆），或先 `split` 再按章做。
- 两边都空 → 换关键词（作者、书名片段、丛书名）再查。

**(a) 用户直接给了页码** → 跳到第 2 步。

**(b) 用户只说内容（如「拉格朗日中值定理那节」）** → 先判断这本 PDF 有没有文字层：

```powershell
$根 = "D:\数学书库"
& "$根\工具\py.cmd" "$根\工具\pdfkit.py" info "<PDF>"
```

- `has_text_layer: true` → 用关键词检索定位：
  ```powershell
  & "$根\工具\py.cmd" "$根\工具\pdfkit.py" find "<PDF>" 拉格朗日中值定理 --context 2
  ```
- `is_scan: true`（扫描版）→ 出缩略图，自己看图定位：
  ```powershell
  & "$根\工具\py.cmd" "$根\工具\pdfkit.py" sheet "<PDF>" --pages 1-24 --cols 4
  ```
  先看目录页拿到章节起始页，再对目标区间出一张更细的拼版确认。缩略图只用来认页码和标题，**不要**从缩略图读公式。

**(c) 用户描述含糊** → 先按 (b) 定位出 2–5 页的候选区间，在回答开头写清「我打算提取 p.120–123，对吗」，不要一次渲一大片。

**(d) 用户按章说事（「概率论第四章」「高代白皮书第九章」）** → 直接用章号定位：

```powershell
& "$根\工具\py.cmd" "$根\工具\pdfkit.py" lookup 概率论 --chapter 4
```

返回 `chapter_lookup.result` 就是那一章的文件，后面的 `--pages` 用**章内页码**（第 1 页 = 该章首页）。
书里有 `c00 前置`、`c99 附录`，也按章号查：`--chapter 0` / `--chapter 99`。

若 `candidates` 有多个（比如「高等代数」同时命中「高等代数学」和「高代白皮书」），补一个区分词再查，别乱猜。

## 第 2 步 先校准：这本书走 A 还是 B（每本新书一次）

挑**公式最密**的一页（不是最干净的一页）当探针，两条通道都跑：

```powershell
$根 = "D:\数学书库"
# A：服务端解析
& "$根\工具\node.cmd" "$根\工具\dsfile.mjs" run "<PDF>" --purpose text_recognition --pages 121 --prompt-file "$根\规范\api提示词_提取.md"
# B：本地渲图，自己看图
& "$根\工具\py.cmd" "$根\工具\pdfkit.py" render "<PDF>" --pages 121 --bands 2 --dpi 220
```

比对后定策略：

| 探针结果 | 这本书的策略 |
| --- | --- |
| A 与图一致 | **A 批量 + 抽样核对**，最省时省费 |
| A 有明显错 | **全程走 B**（本地看图逐页转写），别再浪费 token |

> **实测记录**（本次搭建时验证）：
> - 正常排版的页面（真实 LaTeX 排版、清晰扫描件）：A 通道一字不差，`$`/`$$` 规范也守得住。
> - 低分辨率 / 劣质扫描：A 与 `rich_layout_recognition` **都会自信地编出错误公式**（把一个定理写成 `f(x_0)=f(a)+\frac{f(b-x_0)}{b-a}`），而顺着图逐字看是正确的。
>
> A 的错有个讨厌的特点：**结构像模像样，只有系数、下标、定理编号错**。不看图绝对发现不了。所以「A 出稿」之后，公式密集页一律要有 B 的核对或自检兜底。

## 第 3 步 服务端解析（A 通道）

```powershell
$根 = "D:\数学书库"
& "$根\工具\node.cmd" "$根\工具\dsfile.mjs" run "<PDF>" --purpose text_recognition --pages 120-122 --prompt-file "$根\规范\api提示词_提取.md"
```

- `purpose`：纯文字页用 `text_recognition`；页面上的图/表必须保留时换 `rich_layout_recognition`。
- 只提一部分（某定理、某几道题）就追加 `--prompt "只输出习题 4.2 的第 3–5 题"`。
- 单次输出别超过约 20 页（`max_tokens` 是 16000，超了会截断）。
- 首次 `run` 会上传并解析（按页计费一次）；同一本书后续页用 `ask --file-id` 复用，不再计解析费。

## 第 4 步 核对（A 的结果不是最终答案）

以下任一情况必须做本地看图核对：

- 出现 `⍰`、或翻译腔表达、或明显丢行漏段；
- 该页有分式、矩阵、积分上下限、分段函数、上下标嵌套；
- 页眉页脚、双栏排版（公式串到隔壁栏）；
- 用户明确要求「一字不差」。

```powershell
& "$根\工具\py.cmd" "$根\工具\pdfkit.py" render "<PDF>" --pages 120-122 --bands 2 --dpi 220
```

然后**按顺序逐张读图**（`p0120-1.png`、`p0120-2.png`……，相邻带之间有 6% 重叠，重叠处不要重复输出）。以图为准，逐行改掉 A 的错处。

> 渲染图自动落在 `缓存\<书名>\pages\`——多本书共用一个工作区也不会串页。
> `--bands 2` 把每页切成上下两带，保证读图时是原生分辨率、不被压缩；公式特别密或字号很小就 `--bands 3 --dpi 260`。

## 第 5 步 自检

把成品写到 `$根\缓存\_check.md`，然后：

```powershell
& "$根\工具\py.cmd" "$根\工具\pdfkit.py" verify "$根\缓存\_check.md" --tex
```

`ok: true` 才交付；否则按 `errors` 修完再跑。**这一步不能跳过**——禁用结构和 `$` 未配对靠肉眼看不出来。

## 第 6 步 交付

一个代码块，块外最多三行说明。示例：

````
```text
### 4.2 拉格朗日中值定理

若函数 $f(x)$ 满足：
1. 在闭区间 $[a,b]$ 上连续；
2. 在开区间 $(a,b)$ 内可导，

则至少存在一点 $\xi \in (a,b)$，使
$$
f'(\xi) = \frac{f(b)-f(a)}{b-a}.
$$

**推论 4.2.1** 若 $f'(x)=0$ 在 $(a,b)$ 内恒成立，则 $f(x)$ 在 $[a,b]$ 上为常数。
```
````

块外说明（三行以内）：

```
p.120–122，含定理 4.2 与推论 4.2.1
自检：ok（$ 配对 42 处，LaTeX 编译通过）
存疑：p.121 末行「⍰」疑为「ξ」
```

## 故障对照表

| 现象 | 处理 |
| --- | --- |
| 输出里出现 `\[` `\(` | 没带 `--prompt-file`，或指令被覆盖。重跑并确保带上规范文件 |
| 页码对不上 / 串页 | 上传时 `--pages` 与要求的页码不一致；或书有封面卷首导致物理页≠书页，改用 `sheet` 确认 |
| 公式被压成一行（分式变 `/`） | 该页用 `rich_layout_recognition` 重跑，或直接走本地看图 |
| 输出被截断 | 缩小页范围，一次 ≤ 10 页 |
| `HTTP 400`（上下文/文字量超限） | 缩小 `--pages` 重问，`file_id` 可复用；仍不行走本地看图 |
| `HTTP 400 文件无法解析` | PDF 加了密码，或不是真正 PDF（改后缀的图片集需先转 PDF） |
| `HTTP 413` | 文件超 100 MiB，需要拆或压缩 |
| `HTTP 504` | 解析超时，重试；仍失败就换本地看图通道 |
| 读图时公式看不清 | 提高 `--dpi`，或加大 `--bands` |
| 缓存占空间 | `pdfkit.py prune --days 7`，渲染图都可重建 |
