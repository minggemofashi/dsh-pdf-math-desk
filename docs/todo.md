# 待办 · 最小可执行单元

> **维护者：boss**。其他角色只读；执行者只能更新自己的执行状态，不能自行增删单元。
> 这里只放已经拆好的执行单元；未拆清的需求留在 `docs/requirements/` 或 boss 的输入里，不进入本文件。

## 入队规则

一个单元必须满足：

- **一件事**：一个会话可以完成，且只有一个用户可感知的结果。
- **有边界**：写明涉及的文件/模块；预计超过 2 个文件时，执行前必须另出计划等确认。
- **有验收来源**：只能引用 `docs/requirements/` 的具体小节或 `AGENTS.md` 的硬约束，不能写“看起来正常”。
- **有依赖**：前置单元、环境、数据或用户确认写清楚；依赖未满足不标为可执行。
- **不打包**：不把“顺便修一下”“顺手重构”塞进同一单元；同类但独立的修复拆成独立单元。
- **不重复拆解**：同一个结果被拆成多个会话反复规划时，boss 必须退回原因，不再继续切碎。

## 状态

| 状态 | 含义 |
| --- | --- |
| `待执行` | 已拆好，等待承接角色 |
| `进行中` | 当前会话正在做 |
| `待审查` | programmer 已完成，等 code-reviewer |
| `待测试` | 无 Critical，等 tester |
| `待发布` | 已通过测试，等用户明确发布指令 |
| `阻塞` | 缺依赖/需要用户确认；必须写明阻塞原因 |
| `完成` | 已合入本地或已发布（发布状态另记在 CHANGELOG / Release） |

## 优先级

- `P0`：阻断性 bug、数据损坏、安全问题，或正在阻断发布。
- `P1`：明确的用户可见缺陷或已承诺的功能。
- `P2`：体验优化、文档补齐、非阻断清理。
