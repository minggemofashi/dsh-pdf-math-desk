# 文件布局标准（LAYOUT）

> 本文件是书库与插件数据的**布局契约**，来自 DEC-0014 §2。所有导入、导出、备份、清理都必须按这里的归属执行。
> **目录名不改**：改目录名会破坏既有书库、`索引.json` 与 `.pdfdesk/` sidecar 契约；确需改动时先出新 DEC 与迁移方案，并经用户确认。

## 1. 两个区

书库根（`libraryDir`）下只有两类东西：

- **PDF 区**：`分片/`、`整本/`。放用户自己的 PDF。可以整体压缩后搬到别的机器；备份/迁移包**不含**它们（版权，用户已拍板）。
- **数据区**：`产物/`、`封面/`、`.pdfdesk/`、`回收站/`、`工具/`、`索引.json`。由插件读写，体积小，可以随「导出书库包」迁移。

## 2. 书库内

| 路径 | 区 | 谁写 | 谁读 | 可删性 |
| --- | --- | --- | --- | --- |
| `分片/<书id>/` | PDF | 拆分工具、示例书、书籍包导入 | 目录扫描、阅读器 | 用户 PDF；插件**永不自动删** |
| `整本/` | PDF | PDF 导入、md/txt 渲染结果 | 目录扫描、阅读器、拆分入口 | 用户 PDF；插件**永不自动删** |
| `产物/<书>/<章>/` | 数据 | 翻译、读版、叠加、导出 | 预览、阅读器、导出 | 可由缓存重建，但可能是用户成果；**不自动删** |
| `封面/` | 数据 | 用户放图 | 书架/书库页 | 用户数据；不自动删 |
| `.pdfdesk/annotations/`、`questions/`、`attachments/` | 数据 | 阅读器（标注/疑问/附件） | 阅读器、预览 | 用户数据；**不自动删** |
| `.pdfdesk/` 内其余缓存 | 数据 | 翻译/叠加任务 | 阅读器 | 可重建；设置 → 数据「清除翻译缓存」清理 |
| `.pdfdesk/translation/<书id>/<章>/` | 数据 | 整章翻译的逐页 md / blocks / layout | 阅读器、重建叠加/译文 | 可重建；从旧全局目录迁移时带 `.migrated-from-global` 标记 |
| `回收站/` | 数据 | 删除操作（书/章/产物） | 用户手动 | 用户可「清空回收站」一键清空（需确认）；插件**不自动清空** |
| `工具/` | 数据 | 拆分工具安装 | 拆分会话 | 可重装 |
| `索引.json` | 数据 | 目录扫描与重命名 | 书库加载 | 可重建（扫描回退）；不手改 |

## 3. 插件数据目录（`%DSH_HOME%/pdfdesk`，即 bootstrap 的 `dataDir`）

| 路径 | 归属 | 可删性 |
| --- | --- | --- |
| `libraries.json` | 书库注册表（含各库路径、当前库） | 删了要重新添加书库 |
| `state.json` | 阅读位置、视图、展开状态 | 可删，只丢阅读位置 |
| `pending.json` / `links.json` / `pressure.json` / `shelves.json` | 会话登记、书架分组等 | 可删，丢对应体验 |
| `qa-persona.md` | 问答人格 | 可重建 |
| `deepseek.json` | 旧版 DeepSeek Key（翻译已改走 DSH 模型） | 可删 |
| `fonts/` | 手写字体 | 可重新下载 |
| `translation/<书id>/<章>/` | 逐页译文缓存（md/blocks/layout） | **已迁入书库** `.pdfdesk/translation/`；只保留无法判断归属的旧数据（不删、启动时告警） |
| `translate-jobs/` | 翻译任务状态 | 可删（中断的任务） |
| `backup/` | 迁移包与导入快照 | 可删 |
| `tmp/` | 上传、渲染、拆分临时文件 | 可随时删 |

## 4. 与备份、导出、清理的关系

- **迁移包**（`POST /pdfdesk/backup`）：只含会话、工作区登记、插件状态、书库 `.pdfdesk/`、可选字体/设置；**不含 PDF、译文缓存、产物**。
- **导出书库包**（T-20261126-05，已实现）：`POST /pdfdesk/library-export` 打包 `索引.json` + `.pdfdesk/`（排除 `translation/`）+ 可选 `产物/`，manifest 写 `format: pdfdesk-library-export`、`included.pdf: false`；产物在 `%DSH_HOME%/pdfdesk/backup/library-export-<时间>.zip`，下载走 `/pdfdesk/backup/file`。**不含 PDF**。
- **用户要带 PDF**：自己压缩 `分片/` 与 `整本/`；因为 PDF 都在书库里，压缩包与导出包能对上。
- **清理**（T-20261126-06）：只删可重建的缓存/缩略图/中间 PDF；**永不自动删用户 PDF、标注、疑问、产物**。已实现（T-06a，设置 → 数据「存储占用」）：`tmp/` 里过期上传与页导出临时文件、过期导入暂存包、未完成的 `backup/staging-*`；打包文件（`backup/*.zip`）、导入前快照与 `回收站/` 不参与自动清理，只能由用户点「清空回收站」。
- **设置页只读展示**：设置 → 数据 → 「数据位置」显示书库目录与插件数据目录；「存储占用」显示各区域大小。两者都由 profile 配置（`cordis.patch.yml` 的 `libraryDir` / `dataDir`）决定，**不能在设置里修改**。

## 5. 不变量（改代码前先对照）

1. 目录名与层级不改；新增目录必须在本文登记归属。
2. 插件写入用户目录前先 `mkdir -p`，写入用临时文件 + `rename` 原子落盘。
3. `索引.json`、`.pdfdesk/` sidecar 结构、`~/.dsh/pdfdesk/` 存储键属于受保护契约，动之前出计划并经用户确认。
4. 任何自动删除都只能作用于「可重建」项，并在设置里能看见、能关掉。
