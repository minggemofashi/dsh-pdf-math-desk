10. **书架内也能添加 PDF**：自定义书架（如「高等代数学」）有与书库页同款的添加卡片，顶部面包屑行有「添加 PDF：开/关」并按书架记忆；书架内导入的 PDF 自动加入当前书架（文件仍落 `整本\`）。（`client.js` `importTile` / `toggleShelfAddPdf`。）

## 八、2026-11-27 追加：书架隐藏、拆分回当前书架、拆分会话与勾选记忆

> 用户直接指令与拍板：自定义书架内的书无法隐藏（近世代数基础可复现）；拆分后的书不自动进入当前书架（傅里叶分析）；「打开拆分后的书」没有作用且功能应改为打开最初的拆分会话；需要记忆功能。用户选择：记忆=记住结果框两个勾选；没有拆分会话时自动新建；本轮只修 bug，重构下轮。

### 用户可感知

1. **自定义书架内隐藏生效**：隐藏后卡片立即消失，取消隐藏后回到原书架；书架计数同步。
2. **自定义书架是显式位置**：不再被「整本书 / 未按命名拆分」两个全局开关二次隐藏；否则刚拆出的书即使加入书架也看不见。隐藏书籍页保持原行为。
3. **拆分书自动回当前书架**：在自定义书架里打开整本并拆分，完成后新拆分书自动加入该书架；傅里叶这类文件名截断 id 也能按目录匹配。
4. **拆分完成改为打开拆分会话**：第二项从「打开拆分后的书」改为「是否打开拆分会话？」；本库没有拆分会话时自动新建并打开；打开失败留在弹框提示。
5. **勾选记忆**：点「完成」时记住两个勾选，下次拆完默认沿用；「以后再说」不写入，避免取消也覆盖记忆。

### 原因与入口

- 根因 1：自定义书架分支只按 `activeShelf.books` 取书，未减 `shelves.json.hidden`；隐藏只写 `hidden`，不移出书架。入口：`client.js` 的 Workbench 书架分支（约 `:23860-23875`）与 `Shelf`（约 `:8296-8309`）。
- 根因 2：`/pdfdesk/split` 只写文件；拆分书 id 由文件名截断产生（与整本 id 不同），且全「未命名」时为 `loose`。入口：`SplitDialog.onDone`（约 `:24381-24407`）、`routes.js` 的 `/split`。
- 根因 3：结果框依赖旧 `books` 快照；入口：`SplitResultDialog`（约 `:6125-6200`）与 `reload()`（约 `:20838-20863`）。
- 根因 4：两个勾选无持久化；入口：`readSplitResultChoice` / `writeSplitResultChoice`（约 `:11526-11571`）。

### 内部变化

- `client.js`
  - 新增 `SPLIT_RESULT_KEY = 'pdfdesk:split-result'`、默认值、读写函数；只在 `finish` 成功路径写入。
  - `SplitResultDialog` 的 `openBook` → `openConversation`；`onOpenConversation` 返回 boolean；失败显示 `splitResultOpenFailed`。
  - `reload()` 返回 `Promise<books>`；`reloadWaiters` 在 bootstrap 成功、失败、页面卸载时结算，避免拆分结果等刷新时挂起。
  - `startSplitSession` 返回 `boolean`，无会话时自动新建；`saveShelfGroups` 返回写入 Promise。
  - `SplitDialog.onDone` 等刷新后按 `dir === doneBook.id && whole !== true` 找拆分书，`await saveShelfGroups` 加入当前自定义书架。
  - 父级书架视图对自定义书架排除 hidden；集合卡计数排除 hidden。
  - `Shelf` 用 `explicitShelf`（`group !== null`）跳过整本/未命名过滤，并隐藏开关行。
- 文案：zh/en 改写 `splitResultOpenAsk` / `splitResultOpenHint`，新增 `splitResultOpenFailed`；键结构不变。

## 十、2026-11-27 修复：分片工具打开不相干的会话

> 用户手测第八节结果：「分片工具无法正确新建会话」；追问后确认实际现象是**进入了一个不相干的会话**。本轮只修这一件事；用户已确认的提示词与性能方案见下两轮（另行记录）。

### 原因

三处叠加：

1. **指针没有来源标记**：`pdfdesk:split-session:<库 id>` 只存 `{ sessionId, workspaceId }`，任何旧值/外来值都会被当作本库拆分会话直接 `openSession`。库里最近一个空会话 `session-07e9c716…`（2026-11-27 10:12，354 B，无标题，草稿为空）已在 `workspace.json` 的归档列表中，旧指针完全可能指向它。
2. **打开结果不可信**：`openHostSession` 只要 `uiWorkspace.openSession` 存在就返回 `true`；空 id 或抛错的打开也会被当成成功。空 id 被 Host 当作「当前会话」揭示时，表现就是进入不相干的会话。
3. **指针写得太早**：`writeStoredSplitSession` 在打开之前执行；打开失败（或草稿没写入）的会话也会被记住，下一次继续重开。

### 改动（只 `client.js`）

- 指针写入 `{ kind: 'split', sessionId, workspaceId, cwd }`（`writeStoredSplitSession`，`:676`）；`readStoredSplitSession`（`:228`）只信任带 `kind: 'split'` 的新指针，旧值直接丢弃——下一次点击会新建并写入可验证的指针。

- `openHostSession`（`:4108`）拒绝空 id，并捕获 `openSession` 异常；失败返回 `false`，不再假成功。
- `startSplitSession`（`:23807`）改为**打开成功后才写指针**；重开失败先清指针；打开失败清指针并提示。草稿没写入时也清指针并提示（避免下次重开一个没有提示词的空会话），同时仍保留本次会话 id 的「本页已知拆分会话」登记，防止章节 New 误用。

## 十二、2026-11-27 拆分面板改用 Host 缩略图（WPS 式加速）

> 用户：「现在拆分工具，载入又要载入半天，我看 WPS 的效果几乎都是瞬间完成的呀？参考一下如何去加速，给个方案出来」，并在方案 A/B 中选择 **B（WPS 式 Host 缩略图）**，批准新增 `pdf-info`/`pdf-thumb` 类路由与缩略图缓存。
> 实现按两步落地：Host 渲染/缓存 + 客户端改用图片网格；pdf.js 旧路径保留为 Python/PyMuPDF 缺失时的降级。

### 路由与缓存

- `POST /pdfdesk/pdf-layout`（`:3251`）：按当前书库解析 `book/code`，一次返回 `{ pages, pageWidth, pageHeight, aspect, width, v, rendered }`，并在缓存缺失时用 PyMuPDF 渲染请求范围。范围上限 60 页，宽度 80–480（默认 240）。
- `GET /pdfdesk/pdf-thumb`（`:3304`）：返回缓存 JPEG（`image/jpeg`），带 `ETag` 与一年 `private` 缓存；`v` 与当前 PDF 身份不符时返回 409，提示客户端重新取 layout。
- 缓存：`~/.dsh/pdfdesk/thumbs/<sha1(路径|大小|mtime)>/info.json` 与 `<宽度>/pNNNN.jpg`；身份随文件变化，旧目录不再命中。**没有**写进书库 `.pdfdesk/`（缓存不属于书库数据/备份）。
- 渲染工具：新增 `tools/pdf_thumbs.py`（PyMuPDF + Pillow），页面图 JPEG q80；已存在的页直接跳过；写临时文件后 `os.replace`，避免半张图。

### 客户端

- `SplitDialog` 先请求 Host（`client.js` `prepareHostThumbs`，`:6129`）：首屏 1–12 页；滚动时观察可见页，按 ≤60 页一批补；`splitThumbUrl`（`:5788`）拼出带 `v` 的图片地址。
- Host 模式：每页一个 `<img loading="lazy" decoding="async">`，外框用 `aspect-ratio` 预留高度（`:18567`），不再建 canvas、不再解析 PDF；首屏只显示占位页码。
- `pdf.js` 旧路径只在 Host 不可用时运行（`thumbMode === 'pdfjs'`），阅读器的既有行为不变。
- 图片加载失败会移除地址并重新排队，避免一次瞬时错误永久空白。

### 实测（本机）

## 十三、2026-11-27 修复：拆分件跟随整本所在书架

> 用户：「拆完的书还是不会进入对应的书架，我的意思是，如果一本书被我放进了『数学分析』书架上，那么它的拆分件也应该自动进入『数学分析』」。
> 上一版只在**从该自定义书架里**打开整本并拆分时才自动加入；从书库页/书本页拆分时 `group` 为 null，就什么也不加。

### 原因

- `fileSplitBooks` 只把「拆分时打开的分组」当作目标（`splitShelfTarget(options.group)`）。
- 整本书在哪个书架里，与拆分入口无关；书架成员关系已经存在 `shelfGroups.shelves[].books` 里，只是没被使用。

### 改动（只 `client.js`）

- 新增 `splitTargetShelves(groups, bookId, group)`（`:6774`）：
  - 遍历所有自定义书架，**只要成员里有这本整本书**就作为目标；
  - 整本卡与书架条目都可能带 `@hash` 后缀，比较时两边都用 `wholeBaseId` 归一；
  - 如果拆分是在某个自定义书架里发起的，该书架也加入目标（去重）；
  - 「隐藏书籍」不是位置，永远不作为目标。
- 新增 `shelfAddBooksTo(groups, shelfIds, ids)`（`:556`）：把同一批拆分书一次写进所有目标书架，返回合并后的 groups 与新增数；一次 `saveShelfGroups` 落盘，不再逐个书架写。
- `fileSplitBooks` 改为用 `splitTargetShelves` 算目标、`shelfAddBooksTo` 归档；原 `splitShelfTarget`（只看当前分组）删除。
- 目标书架不只一个时（例如一本整本同时在「数学分析」和「傅里叶」），拆分件会同时进入两个书架。

### 契约

未改路由、`shelves.json` 结构、locale、存储键；只改变“拆分完成后把新书加入哪里”的判定。

### 验证（全部退出码 0）

- `split-completion-test.mjs` 重写为 20 条：整本所在书架自动命中、多个书架、拆分入口书架并集、隐藏书架排除、`@hash` 两种方向匹配、一次写入、已存在不重复写、无成员不写、空刷新仍结算。

### 未覆盖 / 风险 / 手测
