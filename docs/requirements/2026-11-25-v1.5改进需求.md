## 1. 笔、橡皮与光标对齐（#1）

### 1.1 现状

- 用户原话：“笔、橡皮未对齐，实际笔迹在光标下方而不是对齐光标，需要询问我光标样式以及笔迹对齐位置”。
- 坐标换算：`annotPoint` 以当前页节点的 `getBoundingClientRect()` 为标尺，把 `clientX/clientY` 线性映射为 0..1 页坐标，再按共享平面边界裁剪；没有“光标热点 / 笔尖位置”偏移量（client.js:10986–11012；`inkPointOfFree` client.js:6980–6988）。
- 光标：笔为系统 `crosshair`、橡皮为 `cell`（client.js:14185–14187、14054–14056）；没有自定义笔形/笔尖光标，也没有光标样式设置项（设置页页签见 README:133–140，locale 无对应项）。
- 压感：鼠标固定 0.5，触控笔取 `event.pressure`（client.js:11014–11019、7725–7729）；线宽按压力绘制（client.js:7318–7369）。
- 命中容差：橡皮/选择按“约 8px + 半笔宽”命中（`inkReach`，client.js:7168–7170；`inkHit`，client.js:7203–7209）。
- **待复现**：数位板 + 数控笔下的“光标与笔迹错位”。复现条件：Windows 10/11 + 数位板驱动，v1.4.1，单页模式，100%/150%/200% 缩放，用笔在同一物理点落笔，对照光标可见位置与笔迹起点；橡皮同法对照擦除命中位置。

### 1.2 用户场景与期望结果

- 角色/触发与步骤：用数位板写批注的用户；选笔在页面上落笔并对照光标，或选橡皮点击/划过已有笔迹。
- 期望与失败：笔迹落在用户选定的对齐位置、橡皮擦掉光标所指那段、光标样式符合选择；偏差超过拍板阈值、无样式可选或命中位置不一致即失败。

### 1.3 验收标准

1. 按用户拍板的光标样式（Q1-1）与对齐位置（Q1-2），在 100%/150%/200% 缩放、单页/连续/双语三种视图下，笔迹起点与光标可见位置的偏差不超过用户拍板阈值（单位：CSS px）。
2. 橡皮点击/划过的命中位置与光标可见位置一致；判定容差按拍板结果，现状 `inkReach` 规则作为基线。
3. 光标样式在笔/橡皮下即时生效；切到其它工具或关闭阅读器后恢复默认，不改变其它工具的光标。
4. 若拍板为可配置项，设置在重启 DSH 后保持；保存范围按 Q1-5。
5. 不回归：鼠标绘制、压感线宽、页外笔记、缩放后笔迹位置、撤销/重做、阅读器与右栏对同一笔的显示、旧标注数据读取。

### 1.4 明确不做什么

- 不改笔迹平滑算法、压感映射和笔迹渲染风格。
- 不做全项目光标统一，不改其它工具（选择/文本框/形状/疑问）的光标。
- 不改右栏预览的只读标注语义。
- 不要求引入第三方数位板 SDK 或驱动；不替用户选光标样式或对齐位置。

### 1.5 文案敏感点

- 光标样式名称、对齐位置选项的名称与说明。
- 设置项标题、生效范围说明（全局/按工具/按库）。
- 笔/橡皮光标差异的提示点。

### 1.6 未决问题

- **Q1-1 光标样式**（三选一）：A. 保持系统十字 `crosshair`；B. 自定义笔尖光标（笔形/圆点，热点在笔尖）；C. 光标可配置，提供多套预设。
- **Q1-2 笔迹对齐位置**（三选一）：A. 对齐光标热点（笔尖）；B. 对齐光标中心；C. 对齐笔迹中心线。
- **Q1-3 橡皮规则**：A. 与笔同一套光标与对齐规则；B. 橡皮单独一套（如圆环表示擦除范围）。
- **Q1-4 复现信息**：数位板型号/驱动、Windows 版本、“笔迹在光标下方”大约偏多少像素。
- **Q1-5 保存范围**：A. 全局；B. 按工具分别保存；C. 按书库保存。

## 2. PDF 拆分小包与独立仓库（#2）

### 2.1 现状

- 用户原话：“……拆分工具可以从网上借鉴一下开源的项目，将其改造为只有PDF拆分功能的小包，类似WPS的功能面板（如果不清楚我可以截图），配套上传到github上（新建一个仓库），保证极致的体量小的话，可以考虑集成进插件中……在1M以上的话，就不考虑集成进插件里而是建议新建项目，由用户下载。”
- 插件现状是“不做自动拆分”：README:59 写“按章拆分推荐用任意 PDF 工具手动完成。插件不做自动章节识别”；README:192–193 写“不自动识别章节。插件提供拆分工具和命名规则”。
- 插件里的“拆分工具”只是：把 `tools/` 复制到 `<库根>\工具\`，再开一个预设提示词会话（client.js:745–753 文案；`/pdfdesk/toolkit/install` routes.js:1980–1994；`TOOLKIT_FILES` toolkit.js:15–29）；提示词明确“拆分由用户手动做”（client.js:762）。
- 现有可用的按页范围切分在命令行工具里（`pdfkit.py split`，tools/README.md:73、124；pdfkit.py:566），没有任何缩略图面板或插件内 UI。
- 本仓库内没有独立的拆分包/子包（package.json 的 `files` 与 `src/host/routes.js` 均无拆分 UI）；独立 GitHub 仓库本轮不新建、尚未建立。
- 体量参考（本机 v1.4.1 工作树，仅作为口径讨论材料）：`vendor/pdf.worker.min.mjs` 1,265,413 B、`vendor/pdf.min.mjs` 458,705 B、`vendor/host-ui.cjs` 151,713 B；插件自身还包含 `client.js`、`src/`、`tools/` 等。**体积口径（源码/安装包/运行时占用）与是否含这些依赖由 Q2-1 拍板，不能直接拿本行数字与 ≤1 MB 比较。**
- 用户约束：只做 PDF 拆分的小包；WPS 式面板（缩略图，按章/按页选拆点）；新建独立 GitHub 仓库；≤1 MB 才考虑集成进插件，>1 MB 独立下载；借鉴开源必须注意许可（用户提供的材料列出 PDF Arranger GPL-3.0、Stirling PDF open-core、PDFsam Basic AGPL）。

### 2.2 用户场景与期望结果

- 角色/触发与步骤：需要按章拆书、又不愿用命令行的用户；打开面板 → 载入 PDF → 看整本缩略图 → 按章/按页点拆点 → 确认输出。
- 期望与失败：面板像 WPS 一样可视化选拆点、输出按规则命名且可被书库识别、体量达到拍板口径；无书签时仍能按页手选，损坏/加密/目录不可写有可读错误。

### 2.3 验收标准

1. 面板能载入一本 PDF 并显示整本缩略图（按页）；可按章（书签/目录存在时）与按页两种方式选择拆点。
2. 拆点选择有可见反馈（如页间标记），确认前可撤销/重选；确认后生成与拆点一一对应的 PDF 文件。
3. 输出命名与目录规则明确且稳定（沿用现有 `<书 id>_cNN_<章名>_p起-止.pdf` 或用户拍板的新规则，见 Q2-6）；输出可被现有书库扫描识别。
4. 独立仓库可克隆后按仓库文档构建/运行；不依赖本插件运行。
5. 体量按用户拍板口径测量并记录；**≤1 MB 才进入“是否集成进插件”的下一次讨论；>1 MB 明确为独立下载，不进入插件包**。
6. 许可：仓库包含明确的许可声明；若借鉴 GPL-3.0（PDF Arranger）、AGPL（PDFsam）或 open-core（Stirling）的代码，遵守相应许可义务；不得把不兼容许可的代码直接混入 MIT 插件而不声明。
7. 不回归：插件现有“拆分工具：开一个会话”的入口与行为保持不变（除非用户拍板替换）；现有书库、章节命名与整本阅读不受影响。

### 2.4 明确不做什么

- 不做 OCR、扫描件识别、自动章节内容判断。
- 不含合并、删页、重排（除非用户拍板扩展，见 Q2-2）。
- 不把整本 PDF 塞进插件包；不在本轮改插件代码或新建仓库。
- 不把 AI 分析附录里的具体技术选型（pdf.js 复用、路由写法等）当已批准方案。
- 不替用户决定仓库名、许可或体积口径。

### 2.5 文案敏感点

- 面板标题、按章/按页、拆点、预览、导出/下载、取消、失败提示。
- 体积口径说明（源码/安装包/运行时）与“集成/独立下载”的告知。
- 开源来源与许可声明、致谢。

### 2.6 未决问题

- **Q2-1 体积口径**（三选一）：A. 源码体积；B. 安装包/分发 zip；C. 运行时占用（依赖+资源）。
- **Q2-2 功能边界**：A. 只做拆分；B. 拆分 + 合并；C. 再加删页/重排。
- **Q2-3 仓库名与许可**：仓库名待定；许可候选（MIT / GPL-3.0 / AGPL / 其它）待定，取决于借鉴方式。
- **Q2-4 参考截图**：是否需要用户提供 WPS 面板截图作为交互参照（用户已表示可以提供）。
- **Q2-5 拆点依据**：A. 仅手动点选；B. 有书签时自动预填拆点再微调；C. 读取目录页文本推断（是否接受误判）。
- **Q2-6 输出规则**：A. 沿用现有 `分片/<书 id>/` 命名；B. 输出到用户自选目录并沿用命名；C. 新规则（待用户给出）。
- **Q2-7 平台与形态**：独立桌面应用 / 本地网页 / 命令行+简易 UI，待拍板。

## 3. 书库范围放宽（#3）

### 3.1 现状

- 用户原话：“书库显示的书的范围应当放宽，至少应当允许未按照命名改造的书仍然可读可使用功能，由用户自己选择是否在书库中显示。”
- 章节文件必须匹配 `<short>_cNN[_标题].pdf`（index-source.js:16）或 `<short>_<标题>_起-止.pdf`（index-source.js:19、84–101）；不匹配的 PDF 只计入 `unparsed`（index-source.js:344–347）。
- 一个书目录里若没有任何可解析章节，整本书被 `skipped` 跳过（index-source.js:359–362），书库中不出现；只在诊断区显示“未识别（未按章命名）”与跳过数量（client.js:1313、13615–13619、19344–19346）。
- `整本/`（及库根）下的任意 PDF 会作为“整本”书进入书库（index-source.js:403–451），说明“非分章 PDF 可读”已有先例，但只覆盖整本布局。
- 已有“隐藏书籍”是书架分组，按 book id 保存隐藏列表（shelf-groups.js:32–56、85–101；client.js:19466–19507），只能隐藏已经进入书库的书，不能把未识别目录变成可读。

### 3.2 用户场景与期望结果

- 角色/触发与步骤：书库里有非标准命名 PDF（旧书、扫描件、手工整理件）的用户；打开书库 → 打开一本“未改造”的书 → 阅读/翻页/缩放/标注/建会话。
- 期望与失败：未按命名改造的书也能读、能用现有功能，并可由用户决定在书库显示或隐藏；目录无 PDF 时不产生空书，损坏 PDF 有可读错误，混合命名目录里两类内容都能访问。

### 3.3 验收标准

1. 一个未按命名规则命名的 PDF 书目录（含全部未识别、以及标准命名章节与未识别 PDF 混合两种情况）能在书库中被找到，并与标准命名的书一样打开。
2. 该书中的每份 PDF 至少可作为一个可读单元打开，支持翻页、缩放、单页/连续、标注与章节会话入口（按现有可用能力）。
3. 显示与否由用户选择：默认显示或默认隐藏按 Q3-1 拍板；无论默认值如何，用户都能在书库中显示/隐藏该书，选择在重启 DSH 后保持。
4. 不回归：现有命名章节的排序、标题、页码范围推导；`整本/` 行为；隐藏书籍/书架分组；诊断区仍能看到跳过信息；存储键与 sidecar 结构不变。
5. 未识别 PDF 不会被误编号成 `cNN` 覆盖既有章节；不改写用户磁盘上的文件名或目录结构。

### 3.4 明确不做什么

- 不自动改名、移动、拆分或重命名用户的 PDF/目录。
- 不把“未改造”的编号写回磁盘或写进 `索引.json` 契约。
- 不改变“整本”现有行为，不把整本 PDF 拆成章节。
- 不做内容识别/OCR 来判断章节。
- 不替用户决定默认显示还是隐藏。

### 3.5 文案敏感点

- “未改造 / 未按命名”这类称呼。
- 默认显示/隐藏的入口与说明、隐藏后的找回路径。
- 跳过诊断与“可读但不识别”的提示。

### 3.6 未决问题

- **Q3-1 默认行为**：A. 默认在书库显示；B. 默认隐藏，用户手动显示。
- **Q3-2 “未改造”判定**（三选一）：A. 文件名不匹配现有章节/整本命名即算；B. 由用户手动标记；C. 只对“完全无法解析”的目录生效。
- **Q3-3 书内呈现**：A. 每个 PDF 作为一个章条目；B. 作为一个“整本”入口；C. 仅文件列表，不建章。
- **Q3-4 适用范围**：只对 `分片/<书 id>/` 下无 `cNN` 的目录生效，还是任意目录（含库根散落 PDF）。
- **Q3-5 混合目录**：标准命名分章与未识别 PDF 同目录时，如何合并排序与显示。

## 4. DSH 成本与兼容优化（#4）

### 4.1 现状

- 用户原话：“dsh成本、兼容优化必须做，一方面是支持其它API，另一方面是优化启动速度，以及控制提示词，做好提示插件关闭以降低用户的成本，特指插件会拖累dsh启动和增加上下文的这种情况，但如何优化我还没想好”。

## 7. 连续模式疑问框重复加载与 PDF 闪烁（#7）

### 7.1 现状

- 用户原话：“连续模式疑问框经常重复加载，连带着PDF也开始闪烁，需要修复”。
- 疑问数据：`loadChapterQuestions` 一次 `GET questions`，无缓存（client.js:545–552）；三处独立加载都以 `questionRev` 为依赖——章节疑问列表 `ChapterQuestions`（client.js:5931–5947）、阅读器 `ReaderView`（client.js:12408–12426）、右栏 `SidePdfView`（client.js:15614–15627）。一次疑问编辑经共享总线递增 `questionRev`（client.js:3154–3157、3610–3613），三个组件会各重新请求一次。
- 渲染范围：连续模式下只有“当前页”挂载疑问层（`pageQuestions = questions.filter(page === inkPage)`，client.js:12517–12528；`overlay` 只给当前页，client.js:10146–10170）；其它页没有疑问的静态副本（对比墨迹有 `overlayFor`/`StaticInk`，client.js:16039–16045）。
- 当前页判定：`inkPage` 由 `reader.page` 驱动（client.js:10891–10915），连续模式滚动页码报告有 350ms 去抖（client.js:11667–11672、9491–9501）；滚动跨页时当前页切换，疑问层卸载/重建。
- PDF 绘制：`ReaderPage` 画布 effect 依赖 `doc/pageNumber/scale/onError/visible`（client.js:9510–9538）；离开预取带时 canvas 清成 1×1（client.js:9504–9508），滚动时 `visible` 变化会重绘。
- **待复现**：连续模式疑问框重复加载与 PDF 闪烁。复现条件：连续模式，选一本有 ≥2 个疑问框（分布在不同页）的章节，快速上下滚动跨页；用 DevTools Network 记录 `/pdfdesk/questions` 请求次数，同时观察 PDF 是否闪烁；再在阅读器/右栏各新建/删除一次疑问，记录请求次数与闪烁。

### 7.2 用户场景与期望结果

## 8. 单页模式翻页落点（#8）

**状态（2026-11-25 16:45）**：已拍板并实现，自动验证与独立审查通过，待用户手测；见 §8.6 / §8.7。§8.1 的行号为改前基线（HEAD `d8a20d4`），实现后的位置见 §8.7。

### 8.1 现状

- 用户原话：“单页模式左翻页需要回到底部，右翻页需要来到顶部”。
- 翻页动作：`readerPrev` / `readerNext` → `readerPage` → `{ page, jump }`（client.js:17025–17053）；单页模式没有按翻页方向调整滚动位置的逻辑。
- 连续模式的 `scrollToPage` 明确早退于非连续视图（`stage.getAttribute('data-mode') !== 'continuous'`，client.js:11647–11663）；`reader.jump` 的滚动 effect 只在连续模式生效（client.js:11802–11807）。
- 进入单页模式时才把 `scrollTop/scrollLeft` 清零（client.js:9876–9884、11809–11822）；翻页本身不复位。
- 单页视图的页面盒位于可滚动 stage 内（client.js:14035、10171–10189）；只有页面高度超过视口时才会出现纵向滚动。
- 静态结论：翻页后滚动位置保持上一页的偏移；是否出现“上一页停在顶部/下一页停在底部”取决于用户上次滚动位置，**待复现**。复现条件：单页模式，缩放到页面高度大于视口（如 150% 以上），滚到页面中部，点“上一页/下一页”或按 ←/→，观察新页落点。

### 8.2 用户场景与期望结果

- 角色/触发与步骤：单页模式阅读、放大到需要上下滚动的用户；放大 → 滚到页面中部 → 点上一页/下一页（或键盘翻页）。
- 期望与失败：上一页后停在新页底部、下一页后停在新页顶部；落点不确定、出现空白或边界页异常即失败。

### 8.3 验收标准

1. 单页模式且页面高度 > 视口时：上一页（左翻页）后，可视区停在新页底部（可滚动到最底）；下一页（右翻页）后，停在新页顶部。
2. 页面高度 ≤ 视口时：翻页不产生空白或不能滚动的越界；落点按拍板（顶部/居中，见 Q8-2）。
3. 边界页：第 1 页执行上一页、最后一页执行下一页时不改变滚动位置、不报错。
4. 触发方式一致：翻页按钮、键盘（←/→、PageUp/PageDown）、页码跳转按同一规则（若只对部分方式生效，按 Q8-1 拍板）。
5. 不回归：连续模式翻页/滚动、双语两栏、缩放、标注层位置、程序性滚动不发布页码（decisions.md:317）、右栏预览（若适用）。

### 8.4 明确不做什么

- 不改连续模式的滚动规则与页码上报规则。
- 不改翻页快捷键默认值。
- 不新增翻页动画/惯性滚动。
- 不改页码共享状态契约，不让程序性滚动发布页码。

### 8.5 文案敏感点

- 无新增用户文案；若改变翻页提示需另列。

### 8.6 未决问题（2026-11-25 已拍板）

- **Q8-1 触发范围 = A**：翻页按钮 + 键盘（←/→、PageUp/PageDown）+ 页码跳转，同一规则。
- **Q8-2 短页落点 = A**：页面高度 ≤ 视口时，翻页后滚到新页**顶部**。
- **Q8-3 双语两栏 = A**：只改主阅读器单页模式；双语与连续模式不动。
- **Q8-4 记忆粒度 = A**：不做每页各自的滚动位置记忆。

原选项保留备查：Q8-1 A 按钮+键盘+页码 / B 仅按钮 / C 另含滚轮触控；Q8-2 A 顶部 / B 居中 / C 现状；Q8-3 是否双语同规则；Q8-4 是否记忆每页。

## 9. 翻译文字对齐优化（#9）

### 9.1 现状

- 用户原话：“翻译工具需要优化，目前还达不到我想要的文字对齐效果”，并附 AI 分析附录 B（参考输入，未批准）。
- 块解析：PyMuPDF `get_text("dict")` 只输出 `bbox`、`size`（取块内最大值）、`text`（截断 400 字），没有 baseline/leading/font/align（tools/pdf_blocks.py:16–47，其中 45–46 行；分类启发式 84–90）。
- 页图：整章按 140 DPI 栅格化（tools/pdf_raster.py:14；translate-job.js:30）。
- 块翻译：一次视觉请求返回 id→md；模型漏掉的块静默变成空串，无按块重试（translate-blocks.js:125–131）；prompt 未要求“不得合并/拆分块”（translate-blocks.js:13–27）。
- 叠加排版：块宽固定为原 bbox 宽（md2overlay.py:129）；可用高度取到下一块顶部的余量（41–58、120、155）；超出时用 `adjustbox` 整体缩小（158–162）；行距固定 1.25×字号（162）；窄块字号×0.8（137）；同排重叠时右推（93–110）。
- 自动框：按**原文 bbox** 加下边 0.022、左右 0.004 生成（client.js:10829–10849）；框内是整页译文位图，渲染宽度固定 1400px（client.js:10758），再用 `backgroundSize: '100% 100%'` 拉伸到框（client.js:9030、15506）。
- 已有兜底：整页重排时给出说明与“按段落重建（零 token）”（docs/TRANSLATION.md:46–47；client.js:10869 起）。
- 用户可感知的验收要点：框住后不裁字、不重叠、字号有可读下限、首行视觉基线接近原文、任意缩放清晰。上述固定 padding、固定行距、缩字号适配与固定位图宽度都可能影响这些点，**待复现**。
- **待复现**：逐页复现“裁字/重叠/字号过小/首行基线下移/放大模糊”。复现条件：有可用译文与叠加层的章节，100%/150%/200% 缩放，框住不同长度的段落（含末行、公式、脚注），记录框内文字是否被框边裁切、是否与相邻框重叠、最小字号、首行基线差、放大后的清晰度。

### 9.2 用户场景与期望结果

- 角色/触发与步骤：阅读外文教材、需要框选原文看译文的用户；翻译本章 → 打开叠加 → 框住原文段落 → 缩放查看。
- 期望与失败：框内译文完整、不裁字、不与相邻框重叠、字号可读、首行与原文视觉基线接近、任意缩放清晰；末行/标点被裁、框间压字、字号过小、基线偏移或放大模糊即失败。

### 9.3 验收标准

1. **不裁字**：框住任一段落，框内译文完整可见，段落最后一行、标点、上下标不被框边切断。
2. **不重叠**：同一页任意两个框内的译文不互相压字；框内译文不覆盖到框外的原文关键内容（可接受范围按 Q9-3）。
3. **字号下限**：框内正文字号不低于用户拍板下限（Q9-2）；不得出现因适配被压到约 4–6pt 的不可读字。
4. **首行基线**：框内首行文字基线与原段落首行基线的偏差不超过用户拍板容差（Q9-2）。
5. **任意缩放清晰**：100%/150%/200% 缩放及右栏预览下，框内译文清晰可读，无肉眼可见的拉伸变形或模糊。
6. **覆盖与保真**：同一章 ≥N 页（样本量按 Q9-6 拍板）逐页检查；公式、定理号、变量不被改写或丢失（可抽查公式 token/数字）；缺译块显式标记并可见，不静默留空。
7. 不回归：双语并排阅读、整章翻译流程/取消/断点续译、阅读器与右栏叠加、标注/框选/删除/撤销、导出、“按段落重建”、旧翻译缓存可读。

### 9.4 明确不做什么

- 不选技术路线：不把“HTML 文本层 / 新排版引擎 / 新测量库”等写成本需求；是否引入由 Q9-1 拍板后再定。
