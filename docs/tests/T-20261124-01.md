## 失败场景

### F1（W3）：reader 未挂载时，有译文的右栏“叠加”被永久禁用

- **前置**：测试宿主上 c06 有可用译文（`translated-info` 返回 `exists:true`，书库中存在 `_translated.pdf`）；右栏 c06 预览 tab 已打开；reader 未挂载（重启/页面 reload 后只恢复右栏）。
- **操作步骤**：打开 c06 的答疑会话使右栏预览出现；执行页面 reload，或按同一端口重启测试 host 后重新载入页面；观察右栏顶部“叠加”。
- **期望**：按用户 W3 裁决，右栏“叠加”应可用，点击能按需加载译文；状态未知不能永久禁用。
- **实际**：右栏顶部“叠加”`disabled=true`，点击无动作；右栏不发起 `translated-info`/`translate-status` 请求；等待后仍禁用。页面 reload 和真实 host 重启均复现。
- **影响**：重启后只有右栏 tab 的用户无法对有译文的章节打开叠加；验收 2 的“恢复可用”只在 reader 同章挂载时成立。U1 因此判不通过。
- **是否可稳定复现**：是（页面 reload 1/1、host 重启 1/1；同一条件重复可复现）。

### F2（W2）：翻译 job 状态丢失后 translating 永不复位，入口永久禁用

- **前置**：localStorage 存在 `pdfdesk:job:Serre表示论:c06`；测试 job 文件存在且 `status: running`；c06 reader 打开并进入“翻译中”。
- **操作步骤**：删除 job 文件（模拟 Host 重启/任务文件被清理或状态路由失败），等待 reader 下一次轮询（约 2 s）；观察按钮与 localStorage。
- **期望**：状态查询失败时应能复位 `translating` 并可恢复入口；至少不应把失败永久当成“翻译中”。
- **实际**：`translate-status` 404 后进入 `catch`，`translating` 保持 true，两个入口持续 `disabled=true`，localStorage job 键残留，备注保持“翻译中… 0/7”；只有重新挂载 reader 才复位。
- **影响**：Host 重启或任务文件清理后，章节可能一直显示“翻译中”，两个“叠加”入口永久禁用；与 U1 的“翻译中禁用”在视觉上相同，但实际是未恢复的锁死。
- **是否可稳定复现**：是（本轮 1/1；与 review W2 的代码路径一致）。

## 未覆盖与限制

- **W1 未复现**：真实 UI 中从阅读器切到 session/右栏会卸载 reader；无法构造“reader 仍挂载 + 另一章右栏预览”的原地换章。也没有真实 API Key/翻译任务，无法触发 `runTranslate` 完成后的状态回写。review W1 的代码风险保留，未把它算作通过项。
- **测试实例不是用户桌面窗口**：桌面 GUI 在当前沙箱内无法注入鼠标/键盘，故使用独立测试实例 + headless Edge 加载同一 commit 的 `client.js` 做真实 UI 验收；用户当前桌面 DSH 没有重启，测试 host 已按同端口真实重启。该差异可能影响宿主层面的窗口/焦点行为，但 W3 的 reader 未挂载 + 右栏恢复状态已在该实例中实际复现。
- **模式切换方式与覆盖**：真实鼠标点击阅读器“连续”按钮后模式未变化（仍 `data-mode=single`），随后用 JS click 将 c06 切到 `continuous`；但 c06 连续态的竖排按钮没有单独快照，c02 reader 连续态也未单独切换。已确认的是 c02 单页（竖排禁用）、side c02 连续（右栏禁用）、c06 单页（竖排可用）和重开 c06 时竖排可用。门控代码不读页面模式，未发现模式分支；不能把“reader 连续态两入口”写成已独立验证。
- **翻译状态是模拟的**：验收 3 和 W2 使用测试 job 文件 + localStorage 键模拟在途/丢失任务，没有发起真实翻译 API 调用；未验证真实网络失败、任务取消、页面卸载等组合。
- **右栏多实例**：右侧预览为 `keepMounted`，DOM 中可能同时存在隐藏的旧章节 `.md-side`；测试对可见实例取状态，隐藏实例的旧状态不作为验收依据。确认 c02 可见实例为 `disabled=true`，c06 隐藏实例的 enabled 属于其自身章节状态。
- **范围外入口**：右栏竖排工具条里的同名“叠加”（T-20261124-07）和主阅读器顶部横向“叠加”不在 U1 范围；隐藏工具条后仍可见的右栏竖排“叠加”未纳入 U1 判定，只记录。
- **未重跑的检查**：本轮按用户指示不重跑 `u1-test`/`dual-overlay`/`node --check`/`check-keys`/`check-deps`/`host-test`；review 记录中这些已执行，但 tester 不把它们当作独立验收结论。`side-smoke` 未运行/未修复，其既有 window shim 失败（`window.addEventListener is not a function`）不属于 U1 失败依据。
- **未覆盖**：真实 API 翻译完成、翻译取消、真实 Host 重启时正在翻译的竞态、多章/多窗口并发、用户桌面 DSH 的实际窗口行为。

## 结论说明

- 验收 1–4 通过，但 **W3 复现为禁用**：重启后只有右栏 tab、reader 未挂载时，有可用译文的章节右栏“叠加”仍被禁用且不会自行恢复，违反用户 2026-11-24 W3 裁决，故 **U1 不通过**。
- **W2 也已复现**：translate-status 丢失后 translating 锁死，两个入口永久禁用；应与 W1/W2/W3 合并返修。
- **W1 未能复现**（不可达），但 review 的代码风险仍在；修复后需按用户裁决走 **Round 2 审查 + 重测**，不拆多个窗口。
- 本次测试未改代码、测试、CHANGELOG、版本号或角色文档；未发布。证据保留在仓库外工作区 `.dsh-scratch/tester-u1/`（JSON/输出/截图），测试实例与浏览器在收尾时停止。
