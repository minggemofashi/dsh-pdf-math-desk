## 2. 第一性原理分析

### 2.1 不变量（应始终成立）

1. **一个章节同一时刻只有一个“当前页”**（按源 PDF 页号定义），所有视图、工具、批注 key 都从它派生；显示页必须等于这个值。
2. **批注的存储键由（书、章、页）唯一决定**；不同视图对同一页的读写必须落到同一键（双语译文栏的独立笔记除外，已确认）。
3. **用户动作是唯一的状态变更源**；程序性滚动/回填不能反过来伪造页码（回声抑制）。
4. **每个菜单项/按钮对应一个可观察的动作**（页码、缩放、模式、工具、历史栈至少一项变化），否则视为缺陷。
5. **提示词自包含**：模型不应为了找文件花 token；路径必须在会话上下文里。

### 2.2 现状与违反点（代码事实）

- `client.js` 已 **11,339 行**，`ReaderView` 与 `SidePdfView` 各自维护页/缩放/模式/批注状态（`SidePdfView` 在 7165–7187 起）。
- 阅读器与右栏通过 `VIEW_PUBLISHED`（`client.js:1808`）和 `syncView`/`subscribeView`（1843/1871）合并字段；`side` 只发布 `page/mode/annotRev`，`reader` 发布 `page/scale/mode/variant/docRev/annotRev`。**两边都有本地 page 副本**（`SidePdfView:7165` 与 `reader.page`），这就是“显示页 ≠ 内部页”的结构性来源。
- 右栏右键菜单动作集中在 `SidePdfView` 的 `menuActions`（约 8028–8160）：翻页（8051 附近）、缩放（8107）、模式（8122）、撤销/重做（8078/8085）。动作函数存在，但可能因为 **`renderScaleRef` 陈旧、`autoFit` 覆盖手动缩放、菜单 `run` 未执行、或页同步回声** 而表现为“无效果”；需 P0 逐项复现定位。
- 右栏渲染 `PdfViewer` 并传 `overlay`/`overlayPage: page`（8212–8237）；批注 key 用 `page`，但工具落笔时若 `page` 与 PDF.js 实际渲染页不一致，就会出现“页码对但写不上”。
- 会话提示词 `seedFor`（约 10132 起）只带书标题、章标题、PDF 文件名、阅读位置；**没有书库根/书目录/章 PDF 绝对路径**，只给了“产物目录”（10136–10137）。模型只能自己找书 → token 浪费。
- 多批注：阅读器文本工具已有“点另一处保存并新建”的逻辑，但右栏、连续/双语、以及文本与笔迹混排仍有覆盖/丢失路径；需统一到同一个批注存储与图层。
- 模块化缺失：阅读器与右栏各有一套 `annotPoint/annotDown/annotUp`、一套页状态、一套菜单；任何修复都要改两处，导致“改了这边那边坏”。

### 2.3 根因结论（待 P0 用复现确认）

- **页码混乱/工具写不上**：页状态有多个副本（reader prop、side local、PDF viewer 渲染页、批注 key），没有单一事实源。
- **右栏菜单无反应**：动作与视图状态之间靠闭包/ref 手工同步（`renderScaleRef`、`autoFit`、`pageRef`），菜单执行时读到旧值或被自动适应覆盖；部分动作可能只改本地 state 未触发渲染。
- **多批注丢失**：右栏/双语没有走阅读器统一的 `openNote/saveNote`，保存时用旧列表覆盖。
- **找书费 token**：提示词缺少绝对路径。

## 4. 模块化目标

### 4.1 模块边界（先在 `client.js` 内抽工厂，后续可拆文件/打包）

| 模块 | 职责 | 现有代码 |
| --- | --- | --- |
| `createViewStore(bookId, code)` | 单一页/模式/变体/缩放状态；`setPage`/`setMode`/`subscribe`；只由用户动作驱动 | 替换 `VIEW_PUBLISHED` + 两端本地 page |
| `createAnnotationStore(scope)` | 按页读写笔迹/文本/框选；undo/redo 栈；`annotRev` 广播；key 由解析后的页决定 | `savePageAnnots`/`strokes`/`pageHistory` |
| `InkLayer`（组件） | 渲染与指针事件；接收 tool/color/width/page；不再自己管页面 | 阅读器/右栏/双语的 `annotDown/annotUp` |
| `PageView`（组件） | 单页/连续渲染 + 图层挂载；从 viewStore 取页 | `PdfViewer`/`ContinuousView`/`ReaderPage` |
| `SideActions` | 右栏菜单/工具栏动作注册表：输入 viewStore/annotationStore，输出可执行动作 | `menuActions` 8028–8160 |
| `SessionSeed` | 生成带绝对路径的提示词；隐私脱敏 | `seedFor` 10132 |
| `ContextMenu` | 菜单模型与执行；统一 `run` 调用与关闭时机 | `openSideMenu`/providers |

### 4.2 开发要求（写入 AGENTS）

- 新功能优先落模块，不在 `client.js` 主渲染函数里继续堆 if。
- 单次改动涉及共享状态时，先写“状态图/同步点”，再改。
- 每个模块至少一个单测/渲染测试；菜单动作要有“点击后状态变化”的断言。
- 重构与功能分开提交；纯重构提交不得改变行为（用测试兜底）。

## 5. 路线图（P0→P6）

### P0 复现与诊断（不改行为）
- 为 A–F 每一项写复现步骤（页码、侧栏、右键菜单、工具、批注），记录期望/实际。
- 加一个**仅开发可见**的诊断条：显示 `book/code/variant/displayPage/statePage/annotKey/mode/scale`。
- 产出：`docs/DIAGNOSIS-0.73.md`（现象、根因、证据）。

**退出**：每项都有可重复的复现步骤与状态证据。

### P1 单一页状态（核心）
- 引入 `createViewStore`，阅读器/右栏/双语都从它取 `page/mode`；删除两端本地 page 副本。
- 批注 key 由 viewStore 的解析页生成；工具只写解析页。
- 修复“移回去不变”：`setPage` 永远先更新 store 再渲染；回声抑制只用于程序性滚动。
- 明确显示页与 PDF 页的映射（译文 PDF 页数不同时如何处理）。

**退出**：页码框/侧栏/预览/批注 key/撤销栈一致；前后翻与滑回都变。

### P2 右栏模式与菜单动作
- 侧栏工具栏加「单页 / 连续」明确切换。
- `SideActions` 统一实现：上一页/下一页/跳页/放大/缩小/适应/模式/工具/清除/撤销/重做；菜单与工具栏调用同一函数。
- 修缩放：`autoFit` 关闭、`manualScale` 生效；菜单与按钮同源。
- 修工具：工具状态与 `InkLayer` 绑定，菜单/工具栏一致。

**退出**：右键与工具栏每个动作都有可观察效果；有自动化测试。

### P3 批注统一与多批注
- 抽 `createAnnotationStore` + `InkLayer`，阅读器单页/连续/双语/右栏共用。
- 文本：同一页可连续创建多个；保存用 store 最新列表，不覆盖。
- 笔迹/框选：多笔共存；撤销/重做两端一致。
- 右栏右键撤销/重做接到同一栈。

**退出**：同一页多文本/多笔迹均可；两端撤销重做不乱页。

### P4 模块化重构
- 按 4.1 拆分工厂/组件；必要时引入构建步骤（`src/client/*` → `client.js`），但先保证无构建也能跑。
- 清理重复的 `annot*`、页状态、菜单代码；`client.js` 只做注册与组装。
- 每个模块补测试；行为不变。

**退出**：核心逻辑不再在 `client.js` 主函数里重复；测试覆盖模块。

### P5 书库位置与省 token
- `SessionSeed` 注入：书库根、书目录、章 PDF 绝对路径、产物目录；续聊同样带。
- 提示词明确“路径已给出，不要搜索/列举目录”。
- 书库页/章节页提供“复制路径”；隐私：路径只进会话上下文，不写仓库。
- 统计一次“找书”前后的 token 对比。

**退出**：新会话提示可直接定位 PDF；模型不再扫描书库。

### P6 同步决策、回归与发布

- 行为矩阵回归（阅读器单页/连续/双语/右栏 × A–F）。
