# 术语表（terms）

> **维护者：ui-copywriter**。本文件规定面向用户文案的统一说法；代码标识符、数据字段名不在约束范围内。
> **当前基线：v1.4.0（2026-11-24）初始版。** 尚未做全项目文案审计；发现现有 UI 与本表冲突时先记录，不批量强改。

## 产品与模块

| 术语 | 定义 / 用法 | 不要用 / 慎用 |
| --- | --- | --- |
| PDF 阅读 | 产品的用户可见名称；界面标题用“PDF 阅读” | PDF阅读、PDF阅读插件、数学工作台、dsh-pdf-math-desk |
| dsh-pdf-workbench | npm 包名、仓库名、插件 ID；只在技术语境使用 | 当作界面产品名 |
| PDF 阅读工作台 | 需要强调整体形态时的描述，不作为产品名的替代 | 单独用“工作台”指代整个产品 |
| 书库 | 一个库根目录，包含 `分片/` 和/或 `整本/` | 图书馆、资料库、目录（泛指时） |
| 书架 | 某个书库中的书列表视图 | 书柜、书库（不要把两者混用） |
| 书 / 书籍 | 一本 PDF 或一本“整本书”；紧凑界面用“书”，说明性文案用“书籍” | 文档、文件（指代书时） |
| 章节 | 一本书下按 PDF 划分的阅读单元 | 篇、节（除非引用原文结构） |
| 分片 | 按章拆分的书库结构，一章一个 PDF | 切片、拆分文件（作为结构名时） |
| 整本 | 整本书一个 PDF 的书库结构 | 全书（作为结构名时） |
| 阅读器 | 打开 PDF 并翻页/缩放的主视图 | 预览器、查看器（指主视图时） |
| 预览 | 阅读器右侧的同章预览；与主阅读器区分 | 把预览也叫“阅读器” |
| 画布 | 页面及页外可写区域组成的标注平面 | 白板、画板 |
| 页面外区域 | 页面边界之外、仍属于画布的可写区域；简称“页外” | 空白区、额外页 |
| 标注 | 页面上的笔画、文本、形状、框选、疑问等对象；界面统一用“标注” | 批注（新 UI 文案不用）、笔记（泛称时不用） |
| 疑问 | 用于标记待问内容的标注类型 | 问题（除非指聊天里的提问） |
| 会话 | DSH 中的一次对话及其上下文；管理语境用“会话” | 对话（仅指聊天记录本身时可用） |
| 提取 / 答疑 / 习题 | 章节会话的三种模式名 | 总结/问答/练习（作为模式名时） |
| 共享前缀 | 章节文本只读一次、各模式分支复用的基础会话机制 | 缓存、预加载（面向用户解释时） |
| 产物 | 某章生成并归档到 `产物/` 的笔记与文档 | 输出、导出文件（作为模块名时） |
| 附件 | 挂在章节上的 PDF / 图片 | 文件、资料（作为模块名时） |
| 双语对照 | 整章翻译后左右并排的阅读方式；首次出现写全称 | 双语（首次出现时单独用） |
| 覆盖层 | 在原文页上框选区域、框内显示译文的实验功能；首次出现应写“覆盖层（实验）” | 稳定翻译、叠加翻译（不标实验时） |
| 实验 | 功能状态：不建议作为稳定主流程 | 内测、Beta（统一用“实验”） |
| 未实测 | 功能状态：入口存在，但端到端未验证、不能保证可用 | 稳定、可用、正式（在未验证时） |
| 迁移包 | 整机迁移用的打包文件；首次出现需说明“未实测” | 备份包（它不能替代备份） |
| 设置 | 设置面板及其页签 | 配置（面向用户时） |
| 快捷键 | 可录制的键盘操作绑定 | 热键、组合键（作为模块名时） |
| DSH | DeepSeek Harness；全大写 | Dsh、deepseek harness |

## 状态标记

- **实验**：功能可用但不稳定，问题较多；入口、说明、Release 说明都必须保留。
- **未实测**：入口存在，但端到端没有验证；不得写成“支持”“稳定”“可用”。
- “比较稳定”只用于双语等已日常使用、但仍有已知限制的能力；不要扩写成“完全稳定”。

## 写法

- 中文用全角标点；中英文/数字之间加一个半角空格（如 `PDF 阅读`、`Python 3`）。
- 界面标题、按钮、标签不加句末标点；说明性正文用完整句子。
- 按钮用动词或动宾短语：`删除`、`取消`、`重新读取`，不用 `确定`、`好的`（危险操作尤其如此）。
- 页码写 `第 3 页`、`第 3–5 页`；范围用 `–`，不用 `-` 连接页码。
- 省略号用 `…`；引号用 `“”`；破折号用 `——`。
- 快捷键写 `Ctrl+Z`、`Shift+Q`、`←/→`；加号两侧不加空格。
- 百分比写 `80%`；单位与数字之间通常不加空格（`32 GB` 这类按可读性处理）。
- 面向用户统一用“你”，不用“您”；不使用居高临下或责怪用户的语气。
- 用户可见文案不写本机绝对路径、用户名、token、内部命令和实现细节。
- 技术名词大小写固定：`PDF`、`Markdown`、`PPT`、`API Key`、`DSH`。

## 变更

- 新增/修改核心术语必须先在此表登记，并说明旧说法是否需要迁移。
- 不为了“更漂亮”批量替换已上线术语；先出问题清单和替换清单，由 ui-copywriter 记录、programmer 执行。
- 本表与代码/界面冲突时，先记录冲突与影响，不直接按本表强改。
