# 提示模板（templates）

> **维护者：用户/队长（按需）**。本文件给出错误提示、危险操作确认等面向用户文案的结构，不规定具体实现和视觉。
> 使用 `{占位符}`；落代码时由 programmer 负责替换与接线。

## 1. 错误提示

### 结构

```text
标题：{对象/动作}未完成
正文：{发生了什么}。{影响或当前数据状态}。{用户下一步可以做什么}
```

要求：

- 说清“发生了什么”，不贴堆栈、内部错误码、绝对路径。
- 说清影响：数据是否还在、操作是否成功、是否需要重试。
- 给一个可执行的下一步；没有下一步时说明“可以关闭此提示”。
- 不责怪用户，不写“操作有误”“非法输入”。
- 不承诺无法保证的结果（例如“不会丢数据”）。
- 一个提示只解决一个问题；不要把所有可能原因堆成一段。

### 示例骨架

**读取书目失败**

> 请确认书库目录仍然存在，并且根目录下包含「分片」或「整本」，然后重试。

**文件不存在**

> 这个文件可能已被移动或删除。你可以重新读取，或返回章节列表。

**构建/转换环境缺失**

> 当前缺少 {Python 3 / TeX Live / API Key}。{对应功能}需要它才能继续。你可以在设置 → 环境中查看安装入口，或先返回阅读。

## 2. 危险操作确认

### 结构

```text
标题：{动作}{对象}？
正文：这将{具体后果}。{可恢复性：可撤销/不可撤销/会先创建快照}。
主按钮：{动词}{对象}
次按钮：取消
```

要求：

- 标题直接说动作和对象，不写“警告！”“确定吗？”。
- 正文必须写清范围（本页/本章/整本/全部）和后果。
- **可恢复性必须如实**：能撤销就写怎么撤销；不能撤销就明确写“无法撤销”；会创建快照就写快照保留几份。
- 主按钮用具体动词（`删除标注`、`清空本页`、`覆盖导入`），不用 `确定`、`好的`。
- 次按钮统一为 `取消`；默认焦点不要落在危险按钮上（实现层负责）。
- 没有明确后果或范围时，不允许落这个确认框。

### 示例骨架

**删除标注？**

> 将删除{本页/选中的}标注{数量或范围}。{可撤销时：可用撤销恢复；不可撤销时：此操作无法撤销。}

主按钮：`删除标注`　次按钮：`取消`

**清空本页标注？**

> 将删除本页的全部笔画、文本和形状，不影响其他页面。{可撤销性按实际能力写。}

主按钮：`清空本页`　次按钮：`取消`

**覆盖导入？**

> 将用迁移包中的同名文件覆盖当前数据；导入前会创建 `pre-import-*` 快照（保留 3 份）。冲突范围：{范围}。

主按钮：`覆盖导入`　次按钮：`取消`

## 3. 空状态与加载

- 空状态先说明“这里是什么”，再给一个下一步；不要只写“暂无数据”。
- 加载失败要区分“没有内容”和“读取失败”；后者用错误提示模板。
- 不把“未实测”“实验”功能写成正常可用；状态标记放在入口和说明里。

## 4. 文案替换清单（交 programmer）

文案规范**不直接改业务逻辑文件里的内联字符串**。发现内联文案问题时，输出：

```markdown
| # | 文件:行号 | 原文（精确） | 替换为（精确） | 理由 | 影响测试 |
| --- | --- | --- | --- | --- | --- |
```

- 原文必须可精确匹配；多行或模板字符串注明上下文。
- 不改 key、变量名、条件分支和占位符结构。
- programmer 落代码后，由用户验收相关文案；不能只由文档口头确认。

## 5. 独立文案常量 / i18n

- 允许改独立文案常量或 `locale/*.json` 中的**纯字符串值**。
- 只改值，不改 key、层级、占位符名、转义和 ICU 结构；改完必须保证 JSON 合法。
- 需要改 key 或增加逻辑分支时，交 programmer，不直接动。
- 字符串变化可能影响测试断言/截图；在替换清单里标注“影响测试”，交用户验收。

## 6. 禁止

- 不做视觉设计（除非用户明确要求）。
- 不写业务逻辑、不改条件分支。
- 不评价功能设计好坏。
- 不把实验/未实测标记删掉。
- 不用“确定/取消”代替有信息量的危险操作按钮文案。
