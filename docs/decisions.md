# 决策记录（Decisions）

本文件保存**已经确认、会影响后续实现或组织方式**的决策，以及被否决的方案和隐性契约。
它是项目记忆，不是讨论区；没有落盘的结论按未发生处理。

## 使用规则

- 只追加，不删除历史；被推翻的决策标记为“已取代”，并链接到新决策。
- 每条决策写清：日期、状态、决策者、背景、决策、后果、被否决的替代方案。
- 角色文档的规则变更必须经用户确认后才可落盘；确认后由 boss 写入，并在本文件留一条记录。
- 架构实现若与这里的隐性契约冲突，先记录冲突并请用户确认，不静默改契约。
- 状态：`提议中` / `已接受` / `已否决` / `已取代`。

## DEC-0001 · 维护体系的九条初始设计原则

- **日期**：2026-11-24
- **状态**：已接受
- **决策者**：用户
- **背景**：项目已有稳定用户（约 700 次/天下载，主要来自版本更新），但维护成本上升：AI 修一个 bug 容易引入新问题；模块化名义完成但边界未必真实存在；发布链路依赖手动记忆；长会话被压缩后约束丢失。
- **目标**：让生成、验证、发布发生在彼此独立的上下文里；让项目记忆从会话搬进文件。会话是一次性工作台，文件是持久记忆。

### 决策

1. **单会话单任务**：一个会话只做一件事，按任务阶段切分，不按时间或 bug 数量切分。
2. **生成与审查分离**：写代码的人不审自己的代码，审查者在独立上下文中只读。
3. **最小修复**：修 bug 只修根因，不重构、不重命名、不清理无关逻辑。
4. **规则修改须经用户确认**：任何角色文档的变更，必须用户确认后才落盘。
5. **文档瘦身**：`AGENTS.md` 只放硬约束、验证命令和指针，不放教程和 CI 细节。
6. **记忆外化**：会话结束前，值得保留的结论必须落盘到指定文件，否则视为丢弃。
7. **换届靠信号**：上下文稀释有可观测信号，出现即交接换会话，不靠感觉。
8. **角色不膨胀**：新增角色须用户确认；每个角色一次最多提 2 条规则变更。
9. **按发布规模分流**：patch / minor / major 触发不同角色组合，闲职角色不常驻。

### 落地位置

| 原则 | 主要落点 |
| --- | --- |
| 1 单会话单任务 | 各角色文档的“会话边界”；`docs/roles/boss.md` 的路由 |
| 2 生成与审查分离 | `programmer` / `code-reviewer` / `tester` 三份角色文档 |
| 3 最小修复 | `docs/roles/programmer.md`；`AGENTS.md` 第 2 节 |
| 4 规则须确认 | 本文件使用规则；`docs/roles/boss.md`；`docs/roles/feedback-collector.md` |
| 5 文档瘦身 | `AGENTS.md`；细节移入 `docs/ci.md` 等 |
| 6 记忆外化 | 各角色“输出”；需求、决策、待办、交接、功能与文案文件 |
| 7 换届靠信号 | 各角色“换届信号”；`docs/boss-handover.md` |
| 8 角色不膨胀 | `docs/roles/feedback-collector.md`；`docs/roles/boss.md` |
| 9 按发布规模分流 | `docs/roles/boss.md` 的发布规模映射表 |

### 后果

- 同一个需求可能跨多个会话完成；交接成本上升，但换来独立验证和更少的隐性回归。
- 文档必须持续维护；没有写进文件的上下文会在压缩或换届后丢失。
- 九个角色不全常驻：patch/minor 不启动功能盘点员，只有 major 才做全项目盘点与文案审计。

### 被否决的初始方案

这些是在搭建本体系时依据上述原则否决的取舍，不代表用户过去提出过这些方案。

| 被否决方案 | 原因 |
| --- | --- |
| 一个会话里完成需求、实现、审查和测试，省去交接 | 生成者会用自己的假设审自己，缺少独立证据；违反原则 2 |
| 按时间或已修 bug 数量切分会话 | 阶段边界不可预测，容易在半成品状态交接；违反原则 1 |
| 每个需求都启动全部 9 个角色 | 闲职角色常驻会稀释上下文，增加无效成本；违反原则 9 |
| 修 bug 时顺手重构、重命名和清理 | 把根因修复与行为改变混在一起，难以审查和回滚；违反原则 3 |
| 把规则只留在长会话或提示词里 | 压缩后约束丢失，换届不可复现；违反原则 6、7 |
| 先扩角色、再找问题来用 | 角色数量不等于维护质量；违反原则 8 |

## DEC-0002 · Host / 浏览器双半架构与不热更新

- **日期**：2026-11-24（补录既有架构，不是本次新选择）
- **状态**：已接受
- **决策者**：既有实现（本次补录）
- **背景**：插件同时需要 Node 侧文件/路由能力和浏览器侧阅读器 UI。

### 决策

- 插件分为 Host 与浏览器两半；Host 只依赖 Node 内置模块，浏览器侧通过 `window.__ModuleLoader__` 注册 slot。
- Host 不直接访问未声明 inject 的 `ctx.<service>`；用 `ctx.get('<service>')`。
- 客户端改动不走热更新；改完必须重启 DSH 验证。

### 后果

- 不能在 Host 里引入随意的第三方运行时依赖。
- 不能向用户承诺 HMR；验证必须包含重启后的真实加载。

## DEC-0003 · `client.js` 是组装层与固定模块边界

- **日期**：2026-11-24（补录既有架构）
- **状态**：已接受（目标；部分未落地）
- **决策者**：既有实现（本次补录）
- **背景**：`client.js` 体量大，模块化名义完成不代表边界真实存在。

### 决策

- `client.js` 只做组装，不继续堆功能实现。
- 模块边界固定为：`createViewStore`（页/模式/缩放单一事实源）、`createAnnotationStore`（按页数据 + 撤销栈）、`InkLayer`（指针/渲染）、`SideActions`（菜单与工具栏共用动作）、`SessionSeed`（提示词与路径）、`ContextMenu`（菜单模型与执行）。
- 不允许出现第三份页状态、第三套 `annotDown/annotUp`、第三套菜单动作。
- 重构与功能分开提交；纯重构不得改变行为，必须有测试兜底。

### 后果

- 新逻辑先抽模块再接线；边界检查由 code-reviewer 负责，不归 programmer 自证。
- 重复的状态或动作不是“先放这里”，而是需要先停下来设计模块的信号。

### 被否决的替代方案

- “先在 `client.js` 里加一个特判，之后再抽”：已被既有回归证明会把临时路径固化成第二/第三套状态。
- “重构时顺手改行为/文案”：无法把行为变化与结构变化分开验证。

### 2026-11-24 校正 · 目标边界，部分未落地

- **性质**：本节六个模块名是**目标边界**，不是当前代码已实现的边界；不得按“缺失即缺陷”判 Critical。
- **现状（2026-11-24 核对）**：`createAnnotationStore` 存在（`client.js:8091`）；`createViewStore`、`InkLayer`、`SideActions`、`SessionSeed`、`ContextMenu` 五个目标名当前未出现在代码中。
- **代码中实际存在的模块**（与目标名**不建立 1:1 对应**）：`createPlane`（`client.js:6856`）、`createInkEditing`（`:8172`）、`createInkGestures`（`:8340`）、`createQuestionCommitting`（`:8452`）、`createPageDraftStore`（`:619`）、`createDocumentCache`（`:2267`）。
- **判定口径**：目标模块尚未落地只记录，不因“缺失”阻断；只有新增第三套状态/动作、跨模块直接 import 内部实现、或让边界更差时才阻断。大重构必须另立需求，不能因本节自动开工。
- **来源**：用户 2026-11-24 裁决（M1）。

## DEC-0004 · 本地优先的数据布局与隐私边界

- **日期**：2026-11-24（补录既有架构）
- **状态**：已接受
- **决策者**：既有实现（本次补录）

### 决策

- 书库列表与插件设置：`~/.dsh/pdfdesk/`。
- 标注镜像、疑问、附件、缓存：书库内 `.pdfdesk/`。
- 会话由 DSH 保存在本机；不收集遥测、不需要账号、不上传书库。
- 问答与整章翻译只在用户发起时调用模型 API；迁移包不包含书籍 PDF 与凭据。
- `cordis.patch.yml` 必须保持中性；真实书库路径只存在运行时 `libraries.json`。

### 后果

- 测试不得依赖仓库内个人路径；分发副本必须替换为中性配置。
- 迁移包尚未完成端到端恢复测试，对外必须标明“未实测”，不能当唯一备份。
- 覆盖层翻译仍是实验功能；对外文案必须保留实验标记。

## DEC-0005 · 发布门禁：显式触发、独立验证、手动批准

- **日期**：2026-11-24（补录既有发布策略，并与本体系对齐）
- **状态**：已接受
- **决策者**：既有发布策略（用户此前确认，本次补录）
- **背景**：发布链路过去依赖手动记忆，容易漏步骤或带病发布。

### 决策

- 日常只本地提交存档；只有用户明确说「发布 / 发版 / 更新 / 推送」才进入发布流程。
- 发布前必须已有 code-reviewer 无 Critical 的结论和 tester 的通过结论；不满足就停。
- release-manager 只做版本号、CHANGELOG、tag、CI/Release、npm 与市场索引同步；不改 `src/`、不改测试。
- 构建失败时停止并退回 programmer，不允许 release-manager 改代码“修构建”。
- npm 发布由用户完成 2FA/批准；Agent 只给登录或批准网址，绝不索要验证码、密码或 token。
- 版本号、`package-lock` 根版本、tag、GitHub Release、npm 版本、分发 zip 文件名必须一致。

### 后果

- 发布不是日常提交的一部分；测试通过也不会自动发版。
- 具体命令、历史坑和当前 CI 状态见 `docs/ci.md`；详细 runbook 保留在 `docs/RELEASE.md`。

## DEC-0006 · 报告落盘、状态所有权与纯文案通道

- **日期**：2026-11-24
- **状态**：已接受
- **决策者**：用户

### 决策

1. **报告落盘**：审查结论只由 code-reviewer 写 `docs/reviews/<单元ID>.md`，测试结论只由 tester 写 `docs/tests/<单元ID>.md`；含单元 ID、commit、依据、结论、证据、未覆盖项、轮次；修复后追加 `Round N`，不覆盖历史；release-manager 发布前必须读这两份文件的最新一轮，不再依赖会话口头结论。
2. **状态所有权**：boss 负责新增、拆解、优先级、验收来源、关闭；programmer 置 `待审查`（不预填报告路径）；code-reviewer 置 `待测试` 或 `退回执行`；tester 置 `待发布`、`退回执行` 或 `阻塞`；release-manager 置 `完成`（= 已发布）。当前环节角色只改状态和报告链接，不改范围、验收标准或新增单元。
3. **纯文案通道**：只改纯字符串值（`locale/*.json` 的值、独立文案常量）的 diff 仍由 programmer 落地；不得改 key、层级、占位符、条件分支或逻辑；必须过语法校验与构建，跑受影响 smoke；不重复完整功能测试。内联字符串、prompt、错误分支、危险操作流程不享受该通道。
4. **文案责任**：ui-copywriter 只维护 `docs/copy/` 规范并核对落地 diff 只含字符串值，不直接改业务文件；文案验收由 ui-copywriter 或用户完成，tester 只验证行为/入口、不评价措辞；纯文案 diff 不使既有功能测试结论整体作废。
5. **`待发布` 之后的纯文案改动**走：`待发布` → `进行中`（programmer 只改字符串）→ ui-copywriter 验收 → tester 只跑受影响 smoke → 回 `待发布`。

### 被否决的方案

- **“文字免检”**：文案改动完全不过验证。否决原因：无法区分纯字符串与逻辑/结构变化，且 `locale` 结构受契约保护。
- **让 tester 给文案质量盖章**：否决原因：把文案质量混进功能验收，tester 无法据此判定，且违反“文字与功能分开”。
- **由 ui-copywriter 直接改 `locale/*.json`**：本轮取“programmer 单写者”，避免同一次改动两个写者。

## 隐性契约（补录）

以下是当前实现和用户约定依赖、但不一定写在接口注释里的约束。改动前先确认，不要靠推测。

- **仓库边界**：`index.js`、`client.js`、`src/`、`locale/`、`vendor/`、`tools/`、`samples/`、用户文档进 git；`node_modules/`、`dist/`、`.dsh-scratch/` 和含本机路径/凭据的文件不进 git。
- **配置中性**：`cordis.patch.yml` 不写具体书库路径，示例只放注释；真实书库列表由运行时 `~/.dsh/pdfdesk/libraries.json` 管理。
- **访问检查**：`/pdfdesk/*` 路由接入 DSH `connection.requestRejection`；不要绕过。
- **PDF 路由**：支持 Range / ETag / 304 与并发 GET 去重；修改时保持这些语义。
- **跨视图状态**：`page`、`mode`、`zoom`、`tool`、`annotations`、`masks`、`scroll`、`variant`、`docRev`、`annotRev` 是共享状态；程序性滚动/回填不得发布页码（回声抑制），用户动作才是唯一变更源。
- **双语页码**：双语两栏页码不同步（v0.72.5 已确认），译文栏笔记独立保存；不要再把两栏页码当成同一个状态。
- **文档现状**：README 仍写“两栏共享页码与翻页”，与上述既有约束不一致；下次 major 由 feature-inventory 核对并修 README，未确认前以既有约束为准。
- **会话共享前缀**：章节文本只读一次，隐藏基础会话按模式 fork；扫描件无法提取文本时回退普通会话。不要改成每个模式重复读整章。
- **数据兼容**：旧 localStorage 笔记会在首次打开章节后迁移到 `.pdfdesk/annotations/`；不得为了新功能破坏旧数据读取。
- **版本一致性**：版本号同时出现在 `package.json`、`package-lock.json` 根、README 安装说明、tag、GitHub Release、npm 和 zip 文件名；发布时逐项核对。
- **实验标记**：覆盖层翻译是实验功能；整机迁移包尚未完成端到端恢复测试。README、CHANGELOG、Release 说明不得把这些写成稳定能力。
- **平台**：只声明 Windows 10 / 11（x64）；macOS / Linux 未适配、未测试，不能承诺可用。
- **不热更新**：客户端改动必须重启 DSH 后才能验证。
